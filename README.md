# Post-quantum TLS in OpenSSL 3.4.1 and 3.5.0 — measurement archive and analysis

Research data and analysis code for the article

> V. Dubetskyy and M.-D. Cano, “A Systems-Level Performance Study of Post-Quantum TLS with ML-KEM and ML-DSA in Modern OpenSSL,” *Information* (MDPI), under review, 2026.

The repository contains (i) the complete archive of benchmark records used in the article, unchanged; (ii) the benchmark suite that produced them; and (iii) standard-library Python scripts that recompute every number, table and figure reported in the article from the raw records.

## Quick start

```bash
python3 analysis/run_all.py        # verifies data/SHA256SUMS, then writes results/
```

Python ≥ 3.9, standard library only (about one minute). Figures are also drawn if `matplotlib` is installed. Nothing in `data/raw/` is modified, and no benchmark is re-executed.

The benchmark suite's unit tests run with `pip install -e . && pytest` (Python ≥ 3.11).

## Statistical conventions

* Percentiles use linear interpolation at (n − 1)·p, the rule implemented in `src/pqc_bench/stats.py` and used when the records were written; recomputed values match the stored summaries.
* Latency percentiles are computed over successful requests. Requests that exceed the 5 s timeout are counted as failures and reported separately.
* Confidence intervals are **within-run** intervals: percentile bootstrap (10,000 resamples, fixed seed) for medians and differences of medians, and distribution-free order-statistic intervals for p99. They describe sampling uncertainty among the requests of one recorded run, not run-to-run variability. Most conditions were recorded once.

## Limitations of the archive

See `docs/PROVENANCE_AND_LIMITATIONS.md`. In brief: the exact source commit, build options and liboqs version of the original runs were not recorded; the records do not identify which provider executed a given algorithm; binary packet captures were not retained (only parsed per-connection summaries); the `retransmissions` and `out_of_order` fields of the packetization summaries are not populated by the parser and must not be read as measured zeros; and phase-level timestamps were not recorded.

## Citing a fixed version

The article cites release **v1.0.0** of this repository. Later commits may add material but do not alter `data/raw/`.
